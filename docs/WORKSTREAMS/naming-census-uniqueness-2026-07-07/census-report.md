# System-name collision census

Workstream: `naming-census-uniqueness-2026-07-07`, AC3. Generated by
`scripts/name-census.mjs` — re-run with `node scripts/name-census.mjs`.
This is evidence for Max's AC5 design review of the proc-gen naming
scheme, not a pass/fail test. No dates or run-specific values appear
below (see "Determinism").

## Methodology

### What is being measured

This tool calls the real, unmodified `generateSystemName()` from
`src/generation/NameGenerator.js` — the function every real naming call
site in the game ultimately calls — through the exact RNG-chaining
pattern production code uses:

```
const nameRng = new SeededRandom(seedString).child('names').child('system');
const name = generateSystemName(nameRng, galacticPos);
```

That chain is reproduced verbatim from 4 real call sites:
`src/main.js` ~4192-4193 (final spawn, via `generateSystemNames`'s
internal `rng.child('names').child('system')`), ~9481-9482 (sky-click
target selection), ~9492-9493 (screensaver auto-select), and the
~9541-9549 feature-routed variants of both. Nothing in NameGenerator.js
or SeededRandom.js is modified, mocked, or stubbed.

### Sampling

For each of the four region buckets (core / arm / rim / halo) this tool
draws 30,000 independent system-name samples
(120,000 total), each built from:

1. **A seed string**, shaped like one of the three real production
   seed-string templates (`warp-star-<n>`, `warp-nav-<n>`,
   `feat-<n>`), chosen in a fixed 7:2:1 pattern (star-click : nav :
   feature) per 10 samples. The 7:2:1 split is a **documented
   assumption**, not measured telemetry — the game does not currently
   log which targeting path players use. `<n>` is a per-family
   counter that only increases across the whole run, mirroring how
   `seedCounter` / starfield index behave in one continuous session.
2. **A galactic position**, sampled *uniformly* within that region's
   geometric definition from `_classifyRegion` (`NameGenerator.js`
   ~275-300): halo is `|y| > 2.0` kpc (checked first, wins regardless
   of radius); core is radius `< 3.0` kpc; rim is radius `> 14.0`
   kpc; arm is everything else. Bounds derive from `GalacticMap.js`
   (`GALAXY_RADIUS = 15` kpc, `GALAXY_HEIGHT = 3` kpc).

A fifth, much smaller supplementary run
(5,000 samples) covers the
no-position spawn fallback — see "Path E" below — which is a distinct
code branch, not a fifth region, so it is kept out of the four-bucket
headline numbers.

### Classification method (catalog / greek / fantasy)

Every generated name is classified by its **output shape**, not by
instrumenting which internal branch of `generateSystemName` fired:

- `catalog` — matches `PREFIX` + separator + digits (e.g. `HD 47832`,
  `TRAPPIST-12`), where `PREFIX` is one of the 15 catalog prefixes in
  `CATALOG_FORMATS` (~:78-95).
- `greek` — matches `GreekLetter Constellation NNNN` (e.g. `Alpha
  Centauri 4821`).
- `fantasy` — everything else. `NameGenerator.js` actually has three
  non-catalog, non-greek branches (pronounceable word, prefixed word,
  word+title) but all three produce pure-letter output with no
  digits, so they are visually indistinguishable as *names* and the
  contract asks for a 3-way split, not 5-way.

This is regex-on-output, which stays correct even if the internal
branch structure changes later, as long as those three output shapes
hold. **Self-check:** the measured catalog/greek/fantasy split per
region is compared below against `NameGenerator.js`'s own configured
`REGION_STYLES` weights (~:307-312) — a classifier bug would show up
as a mismatch here, not silently.

### Determinism

Every RNG draw traces back to a fixed string seed
(`name-census-positions-v1` for positions; `warp-star-<n>` /
`warp-nav-<n>` / `feat-<n>` / `system-<n>` for naming, exactly as
production code seeds them). No `Date.now()`, `Math.random()`, or
other non-deterministic input reaches this report. Verified by
running `node scripts/name-census.mjs` twice and diffing the two
`census-report.md` outputs byte-for-byte (identical; see the tool's
own verification note in the workstream handoff).

Determinism fingerprint (FNV-1a over sorted summary stats): `2c4efd80`

### Known limitations (read before trusting these numbers as a ceiling or floor)

- **Uniform position sampling, not density-weighted.** Real players
  spend disproportionate time near dense regions (Sol, known
  systems, tagged features, popular arm sectors) — real per-sector
  collision pressure in those hotspots is likely **at or above**
  what a uniform sample shows here, not below it. Treat these numbers
  as a reasonable baseline, not a worst-case bound.
- **7:2:1 call-site family mix is an assumption**, not measured
  telemetry (see Sampling above). It changes which seed-string
  template feeds a given sample; it does not change what
  `generateSystemName` does with a given (seed, position) pair.
- **"Distinct systems" here means distinct (seed, position) draws**,
  each treated as a first encounter. This tool does not model a
  player re-visiting the same physical system (that's AC7, a
  separate, later increment) — it measures the AC3/AC6 question:
  do two *different* systems ever get the *same* name.
- **HYG cross-check is exact-string, case-sensitive.** That is the
  operationally meaningful definition (identical on-screen text is
  what would actually confuse a player); it will not catch
  near-miss spellings.

## HYG cross-check (procgen vs. real star names)

`public/assets/data/hyg-stars.json` ships 15,599 entries
(the HYG v4.0 naked-eye catalog, per `RealStarCatalog.js`). Read
directly here (not via `RealStarCatalog`'s browser `fetch()`, which
this headless tool has no equivalent of) — it's the exact same JSON
payload the game loads at runtime, so this is not a different data
source, just a different way of reading the same file.

**Data-quality caveat, discovered while building this cross-check:**
15,243 of the 15,599 entries
(most of the unnamed stars) have `name` set to the literal
one-character string `"` rather than `null` or an `HD ####`
designation. `scripts/process-hyg-catalog.mjs` (~106-113, current
version) falls back to `HD ${hd}` or `null` for unnamed stars — the
shipped `hyg-stars.json` does not match what that script currently
produces, suggesting it predates the current fallback logic or was
generated by a different code path. This is a **pre-existing data
artifact, not something this census tool introduces or fixes** (out
of scope for AC3 — it touches a production asset file, and this
workstream only adds a standalone tool). It matters here because a
naive collision check against the raw 15.6k-entry `name` field would
report ~15,243 "real names," all of them the same useless `"`
character — so this cross-check uses the 355
*distinct, non-artifact* names instead (proper names like `Sirius`,
`Aldebaran`, plus a handful of Bayer+constellation designations like
`p Eridani`).

## Path E — no-position spawn fallback (supplementary, not part of the 4-region headline)

Reproduces `src/main.js` ~4192-4193 for the branch where
`systemData._warpTargetName` is falsy: `generateSystemNames` is
called with no 4th argument, so `_classifyRegion(null)` always
resolves to `{ region: 'arm', sectorCode: 0 }` — **regardless of
where the system actually is.** `sectorCode === 0` is falsy, so
`generateSystemName`'s `nameRng = sectorCode ? rng.child(...) : rng`
skips sector-derivation entirely: this path gets **zero** sector
mixing, unlike every position-aware call site measured above.
