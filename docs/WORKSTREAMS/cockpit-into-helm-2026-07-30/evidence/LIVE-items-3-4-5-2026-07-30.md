## Item 5 — the wheel channel. The one with a new mechanism, so it gets a control.

The claim is not "the map zoomed". It is **"the map zoomed AND the four camera
wheel handlers did not run"** — because the failure this could ship is the map
and the chase distance moving together on one gesture, which looks like a
sensitivity bug and not a routing bug.

`defaultPrevented` was measured first and **discarded as an instrument**: it
read `true` even for a wheel the router refused, because one of the canvas
handlers preventDefaults to suppress page scroll. It cannot tell "the cockpit
consumed it" from "something else did". Replaced with a probe listener bound
**bubble-phase on the canvas** — the exact position `CameraController`,
`ShipCamera`, `ShipCameraSystem` and the idle-timer handler occupy — counting
how many times the event reached them.

| gesture | map `_systemZoom` | camera handlers reached | router census |
|---|---|---|---|
| zoomed, wheel **on** the glass | 1 → **1.15** → 1.0005 | **0** | +1 per wheel |
| zoomed, wheel **off** the glass | unmoved | **1** | unmoved |
| **at rest**, wheel on the same pixel | unmoved | **1** | unmoved |

Row 1 is the feature. Rows 2 and 3 are what keeps the world wheel working: the
gate is the landed panel, not the cockpit's mere presence, so scrolling
anywhere else — and scrolling anywhere at all with nothing zoomed — still
reaches the camera exactly once.

The sign survives the trip: −120 grew the zoom 1 → 1.15, +120 shrank it back to
1.0005 (= 1.15 × 0.87, `_handleWheel`'s own SYSTEM-level factors).

The census gained a `wheel` field and it moved from 0 → 3 across the run, read
off `window._cockpit().pointer`. Counted at the ROUTER, not at the host: a host
that believed it forwarded wheels and did not would otherwise report its belief.

### ⚠ One reading that looked like a regression and is not

The minimap did **not** appear in ORRERY after the flip, and the handoff warns
by name that `e22dd02` shipped a retirement whose *restoration* was silently
broken. Chased rather than assumed:

- **Control**: a fresh page booted **straight to ORRERY**, never entering HELM,
  warped and arrived — slot still null. So it is not the flip.
- **Cause**: `src/main.js:347`, `let minimapVisible = false; // off by default —
  toggle with R key`. There was nothing to restore. ⚠ Note the adjacent
  inconsistency, pre-existing and NOT touched here: `localStorage` carries
  `showMinimap: true`, and the settings applier only runs on *change*, so the
  persisted value never reaches the initialiser.
- The minimap branch in `_hudSlotScene` is **byte-identical** before and after
  this change; only the `'well'` line was removed.
